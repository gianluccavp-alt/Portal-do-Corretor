# Maquete 3D Interativa (Village Gaia) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Criar a página `maquete.html?e=village-gaia`: as 3 torres do Village Gaia em 3D, onde cada unidade acende conforme o status ao vivo da planilha e o clique abre um painel com planta, sol, valores e atalhos para os simuladores.

**Architecture:** As regras ficam num módulo puro, `assets/maquete.js`, testado com `node --test`: grade de unidades, status, % vendido, busca, filtros e navegação. A cena 3D (`assets/maquete-cena.js`, Three.js por CDN) recebe só arrays de estado e devolve eventos. A UI (`assets/maquete-app.js`) liga planilha, módulo e cena. O app nasce com um **modelo provisório gerado em código**, e o `.glb` modelado no Blender entra depois trocando só a config. Os dois seguem o mesmo contrato: uma malha `unidades` com o atributo de vértice `_unit`.

**Tech Stack:** HTML/CSS/JS puro sem build, Three.js `0.170.0` via importmap (jsDelivr), GLTFLoader + DRACOLoader do mesmo pacote, Blender (Homebrew) + blender-mcp para modelagem, `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-02-maquete-3d-design.md`

## Global Constraints

- Site 100% estático: sem build, sem bundler, sem framework e sem `package.json` novo. Os scripts de terceiros vêm de CDN com versão exata.
- A identidade é a do Grupo Direcional: vermelho `#E4032B` (escuro `#B8001F`), DM Sans. Nada do legado dourado/Playfair.
- Nunca exibir na maquete: folga de tabela, valor comercial mínimo, B.A., folga campanha, folga volta ao caixa, valor de avaliação.
- Valores exibidos vêm só de `associativoOf(u)` e `tabelaDiretaOf(u)` de `assets/data.js`, com `activePremio` no padrão `'com'`.
- Grade do Gaia: torres 1, 2 e 3; andares 0 a 19 (0 = garden/térreo); finais 1 a 8. Total de 480 posições, todas definidas em `config.js`.
- Status: `Disponível`/`Mirror` → `disponivel`; `Reservada*` → `reservada`; posição sem linha numa torre à venda → `vendida`; torre sem nenhuma linha → `fora`; planilha não carregou → `sem-dados` (nunca aparece como disponível).
- `solNascente.default` = finais `[1, 2, 7, 8]`, válido para as 3 torres.
- Código da unidade: `BL<torre 2 dígitos>-<andar 2 dígitos><final 2 dígitos>`, ex.: `BL01-1204`, `BL02-0007`.
- Carregamento total em até 15 s, com barra de progresso. O `.glb` deve ter no máximo ~15 MB.
- Idioma pt-BR. Comentários e nomes seguem o estilo dos arquivos vizinhos (português, sem acento nos comentários de JS).
- Prioridade de qualidade no desktop/notebook. No celular a página precisa abrir e funcionar.

## Review Focus

1. **A planilha falha ou passa de 15 s:** nenhuma unidade pode aparecer acesa ou verde. A tela mostra o erro e oferece "Tentar de novo".
2. **Linha da planilha fora da grade** (andar 20, final 9, `BL-04`): ela é ignorada sem quebrar a página, e a contagem aparece no console.
3. **Duas linhas para a mesma posição:** vale a mais conservadora (`reservada` vence `disponivel`) e nunca acende em dobro.
4. **Busca por texto inválido ou unidade fora de venda:** aparece "Unidade não encontrada" ou "Torre fora de venda" e a câmera não se mexe.
5. **A Torre 3 aparece na planilha no futuro:** ela passa a funcionar sozinha, sem mudar código.

**Interfaces:**
- Consumes: unidades no formato de `rowsToUnits` (`bl`, `andar`, `f`, `tipo`, `tipoLabel`, `status`, ...).
- Produces (tudo em `Maquete`):
  - `GradeCfg = { torres: number[], andares: number, finais: number, solNascente: { default: number[] } }`. Andares vão de `0..andares-1`.
  - `indice(cfg, torre, andar, final) -> number`, igual a `((torres.indexOf(torre)) * andares + andar) * finais + (final - 1)`. Fora da grade → `-1`.
  - `posicao(cfg, idx) -> { torre, andar, final }`
  - `codigo(torre, andar, final) -> 'BL01-1204'`
  - `statusDe(texto) -> 'disponivel' | 'reservada' | 'outro'` (normaliza acento, caixa e espaços)
  - `montarGrade(cfg, units | null) -> { celulas: Celula[], torresAVenda: number[], ignoradas: number }`, com `Celula = { idx, torre, andar, final, codigo, estado: 'disponivel'|'reservada'|'vendida'|'fora'|'sem-dados', u: object|null }`
  - `resumo(grade) -> { total, disponiveis, reservadas, vendidas, pctVendido }` (só torres à venda; `pctVendido` vai de 0 a 100 com 1 casa)
  - `nascente(cfg, torre, final) -> boolean`
  - `posicaoLabel(tipo) -> 'Ponta' | 'Meio'` (`tipo` contém `'ponta'` → Ponta)
  - `interpretarBusca(texto) -> { torre: number|null, andar, final } | null`
  - `filtrar(grade, f) -> Set<number>` com `f = { soDisponiveis: boolean, tipos: string[] /* vazio = todos */, andarMin: number, andarMax: number }`
  - `vizinhaDisponivel(grade, idx, dir /* 1|-1 */, visiveis?: Set<number>) -> number | null` (ordem torre→andar→final, dá a volta no fim)
  - `urlsSimuladores(simId, codigo) -> { associativo: string, tabelaDireta: string }`
  - `estados(grade) -> string[]` (o `estado` de cada célula, por `idx`)
